- [#104](https://github.com/ynotdraw/slab-elements/pull/104) [`e431c54`](https://github.com/ynotdraw/slab-elements/commit/e431c5411111cd408b7d7d7672a5e9e07a38ca77) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Checkbox Group's list of checked values moves from `value` to `values`, the way Listbox, Select, Combobox, Tags Input and Toggle Group have it. `value` is now a string, the first of them, and setting it checks only that Checkbox.

- [#152](https://github.com/ynotdraw/slab-elements/pull/152) [`9fee9bf`](https://github.com/ynotdraw/slab-elements/commit/9fee9bfd32bcb920d76b49eb922bfc2a8a48a902) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Checkbox's `indeterminate` is a property only, with no attribute, as on a native checkbox, and resetting its form leaves it as it is. Set it from script.

- [#151](https://github.com/ynotdraw/slab-elements/pull/151) [`838002d`](https://github.com/ynotdraw/slab-elements/commit/838002d26b891672b9c16038fa43df593ffae521) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Dialog, Alert Dialog, Command Palette and Drawer open the way a native `<dialog>` does. The new `showModal()` opens them as a modal. `show()` and setting `open` open them non-modally, so the rest of the page stays usable and Escape only closes them with `closedby`. Dialog, Alert Dialog and Command Palette used to open as a modal from either.

  For a modal opened declaratively, as a framework that binds `open` does, add the new `modal` attribute: `<slab-dialog modal open>` opens as `showModal()` does. A native `<dialog>` has no `modal`, so it's Slab's own. Otherwise, call `showModal()` where you called `show()` for a modal.

- [#103](https://github.com/ynotdraw/slab-elements/pull/103) [`717240e`](https://github.com/ynotdraw/slab-elements/commit/717240efe395fc7545a6768b5913624c6b78ac27) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Grid List's `selection-mode` is replaced by `selectable` and `multiple`, the same `multiple` as Listbox, Select, Combobox and Tree. `selection-mode="single"` is now `selectable`, and `selection-mode="multiple"` is now `multiple`, which makes rows selectable without `selectable`.

- [#114](https://github.com/ynotdraw/slab-elements/pull/114) [`20ee752`](https://github.com/ynotdraw/slab-elements/commit/20ee752d35f3852497bb6648448888c3b614be4e) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Password Field's show-and-hide button dispatches "reveal-change" instead of "toggle". - [#152](https://github.com/ynotdraw/slab-elements/pull/152) [`9fee9bf`](https://github.com/ynotdraw/slab-elements/commit/9fee9bfd32bcb920d76b49eb922bfc2a8a48a902) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Date Picker's and Date Range Picker's `showPicker()` throw as a native input's does: a "NotAllowedError" without a user gesture, and an "InvalidStateError" while disabled or read-only. - [#116](https://github.com/ynotdraw/slab-elements/pull/116) [`916e758`](https://github.com/ynotdraw/slab-elements/commit/916e75876596e6c5b41d416f85a03e08498bb52f) Thanks [@ynotdraw](https://github.com/ynotdraw)! - **Breaking:** Toast's "dismiss" can be canceled to keep the toast shown, as Alert's can. - [#102](https://github.com/ynotdraw/slab-elements/pull/102) [`bcc1f8a`](https://github.com/ynotdraw/slab-elements/commit/bcc1f8ae20ae7e4bf02990da892cbe20259a5ff8) Thanks [@ynotdraw](https://github.com/ynotdraw)! - Every element with `open` now dispatches "toggle" when it opens and closes, as a `ToggleEvent` with `oldState` and `newState`:

  - Menu, Context Menu, Select and Combobox dispatch it for the first time.
  - **Breaking:** Tooltip and Hover Card's "toggle" is now a `ToggleEvent` that, like a popover's, doesn't bubble and isn't composed. Listen on the element itself rather than on an ancestor.

- [#146](https://github.com/ynotdraw/slab-elements/pull/146) [`061e9c8`](https://github.com/ynotdraw/slab-elements/commit/061e9c88801af0573ede146f91d4f9270fd4ece5) Thanks [@ynotdraw](https://github.com/ynotdraw)! - A form control's form data and validity are current as soon as its value changes, as a native control's are, whether the user changed it or code did. Before, they trailed by an update:

  - Inside Radio Group's "input" and "change", `value` and the form data were the previous choice, with both the old Radio and the new one `checked`. Inside Checkbox Group's "input", `value`, `values` and the form data were the previous ones.
  - Inside "input", and sometimes "change", `new FormData(form)` had the previous value for Checkbox, Switch, Text Field, Textarea, Search Field, Password Field, Number, Pin Input, Slider, Range Slider, Rating, Editable, Color Picker, Date Field, Date Range Field, Time Field and File Drop, and `validity` could be stale too.
  - Setting `value`, `values` or `checked` from code, on a control or on a Radio or Checkbox in a group, left `new FormData(form)` and `validity` as they were until the next update.
  - In Date Range Field, `validity` didn't follow when one date moved the other's bound.

  `setCustomValidity('')` on Checkbox, Switch, Rating, Radio Group, Checkbox Group, Combobox, Listbox, Select and Tags Input now clears only the custom error, as it does natively, so a required control that's still empty stays invalid with `valueMissing`. Before, it made the control valid, and once a message had been set, the control stopped validating itself at all.
